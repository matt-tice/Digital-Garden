Summary

Makefiles are collaborations between Make and Bash

Tabs v.s. Spaces

Every command line must start with a single tab

  • if you use spaces you get the missing separator error

Rules

The general structure of a makefile revolves and rules:

target: dependencies
        system_command

Targets

The target is the literal file you want the computer to target

If a file with the target filename is found in the filesystem, Make looks at the dependencies

  • if the dependencies are newer than the target, the command is run and the target file is regenerated

Default

The first target in the file is the default

  • Make will trigger it if no other target is specified

You can specify a target by running make target_name

target_name: dependencies

Phony

If you just want Make to run terminal commands and not create any files, you create a phony target

.PHONY name

Dynamic Targets

We use single dollar signs to represent Makefile variables (as opposed to bash variables) or call built-in Make functions

$(MAKE) runs the command make

Dependencies

When evaluating a target, make will jump down to its dependencies, if they exist

  • if it's not a target, Make will look for the dependency name in the file folder
    • if it exists, it's used as a raw input
    • if it doesn't exist, you get an error

Symbols

$@ Is shorthand for the name of the current target

% is a wildcard

  • you can later reference it with $*

@ tells Make to not echo the command text you wrote

  • by default Make will always print the literal text of the command
  • so if you write echo "hello world", Make will print
echo "hello world"
hello world

Variables

:= declares a variable by evaluating the right side immediately

  • this is faster

= declares a variable, but it doesn't evaluate the right side until the variable is actually used in a command

Semicolons

Bash uses semicolons but Make doesn't. This can lead to some oddness in makefiles — you have to be clear on where semicolons are necessary and where they aren't.

Bash uses semicolons as a newline symbol

Comments

You can't put comments inside of multiline commands being sent to bash

Performance

Make tries to execute every single line as a separate shell command, executed in a separate isolated subshell

To keep multiple lines inside of the same shell (like when doing a for loop) we use

\ to tell us that the end of the current line isn't the end of what to send to this shell

NOTE: when we use \ Make appends the next line to the end of the current one

  • it does not create a new line
  • so usually you need to put a semicolon at the end of the line, before the backslash

Directories

Directories are a bit special when it comes to Make

  • directories are basically text files that list off the names and pointers of the files they contain
  • therefore, a directory's time stamp only updates when the content of the corresponding text file alters
    • which happens precisely when a file inside of the directory is (1) renamed (2) moved (3) deleted (4) created

Changing the content of a file contained in a directory doesn't change its name or pointer, and so doesn't alter the directory's text file or its time stamp
